# 構成と移植性

ゲーム本体はエンジン非依存で、Ebitengine と [sago35/koebiten](https://github.com/sago35/koebiten) の 2 つのフロントエンドがあります。

```
game/            エンジン非依存のゲームロジックと描画
cmd/
  dinosaur-game/ Ebitengine フロントエンド（デスクトップと WASM）
  firmware/      koebiten フロントエンド（マイコン実機、TinyGo でビルド）
internal/beep/   効果音の PCM 生成
targets/         TinyGo のカスタムターゲット定義（ボードごとに 1 ファイル）
web/             WASM 配信用ファイル
```

フロントエンドはどちらも `cmd/` 配下の独立した main パッケージで、共有するのは `game` パッケージだけです。ボードの選択は koebiten 側がビルドタグで行うため、対応ボードを増やすときに増えるのは `targets/` の JSON であって `cmd/` ではありません。

## `game` パッケージの制約

インターフェースは `game/game.go` を読むのが早いですが、なぜその形なのかは以下のとおりです。いずれも「一番非力なフロントエンド（マイコン実機）で動くこと」から来ています。

- **画面は 128x64 の 1bit カラー固定** — 小型 OLED に合わせた。可変にすると実機側で割に合わない
- **描画は `Display.SetPixel` だけ** — koebiten と Ebitengine の描画 API の共通部分がここしかない
- **音は鳴らさず、発生した音を返すだけ** — 鳴らせるフロントエンドだけが読む。フレーム単位なので、1 tick に複数フレーム進めるなら毎回読む必要がある
- **乱数は内蔵 xorshift、`float64` と標準ライブラリ最小限のみ** — TinyGo でビルドできる範囲に収めるため

## ファームウェア（koebiten フロントエンド）

実装は `cmd/firmware/main.go`。実機固有の都合で、他のフロントエンドには無い調整が 3 つ入っています。

- **1 tick に 2 フレーム進める** — koebiten は 32ms tick（約 31 TPS）だが、`game` は 60 TPS 前提で速度を決めているため
- **ナイトモードは塗り潰してから反転** — koebiten v0.5.0 は消灯状態にクリアして点灯ピクセルを描く規約なので、白で塗り潰してから黒で描く
- **乱数シードはプレイヤーの押下タイミング** — ボードには時計が無く毎回同じ状態で起動するため、ランを開始したフレームを `game` 側で混ぜている

`Sounds()` は読みません。音は koebiten の守備範囲外で、鳴らすならこのフロントエンドが自分でブザーを叩くことになります（#23）。
